# E2E シナリオテスト (Playwright)

organisms 以上の画面を、実際の利用の流れ (初回ユーザー登録 → 承認 → メモ登録 → 一覧 → 背景画像 → エディタ) に沿って検証します。

## 実行方法

Docker Desktop を起動したうえで実行します。開発用の DB・MinIO・開発サーバー (3000) とは別環境なので、起動中でも影響しません。

```bash
npm run test:e2e          # 全シナリオを実行 (初回は Chromium のダウンロードに `npx playwright install chromium` が必要)
npm run test:e2e:report   # HTML レポート (スクリーンショット付き) を開く
```

| 環境変数 | 内容 |
| --- | --- |
| `E2E_SKIP_BUILD=true` | 本番ビルドを省略して前回のビルドで起動する (テストコードだけ変更したとき用) |
| `E2E_KEEP_DOCKER=true` | 終了後も E2E 用の Docker を残す (DB の中身を調査したいとき用) |

## 実行環境

`npm run test:e2e` を実行すると、`e2e/server.mjs` が次の順に準備します。

1. E2E 専用の PostgreSQL (5434)・MinIO (9010) を **空の状態で** 作り直す (`docker-compose.e2e.yml`、データは tmpfs)
2. マイグレーションを適用する
3. 本番ビルド (`.next-e2e`) して `next start` (3100) で起動する

- 管理者承認は本番と同じく **必須** (`AUTH_SKIP_APPROVAL=false`)、メールは管理者画面の「ローカル送信メール」で確認します。
- ログインの回数制限 (同一IPで10秒に3回) は本番と同じく有効です。テストごとに別の送信元IP (`X-Forwarded-For`) を付与し、別々の利用者として扱います。
- 画面サイズは iPhone 相当 (390×844)、タイムゾーンは Asia/Tokyo です。
- 終了後、E2E 用の Docker は自動で破棄されます。

## テストの書き方

- テスト名は `「実行動作」__「期待すること」` の形式で書きます (例: `未入力のまま登録する__各項目に必須エラーが表示される`)。
- シナリオは前のファイルの結果 (登録したユーザー・メモ・画像) を前提に、ファイル名の番号順に直列で実行します。単独のファイルだけを実行すると失敗します。
- 管理者 (`salon_owner`) のログイン状態は `01-auth` で保存し、`03` 以降で再利用します (`e2e/.auth/owner.json`)。
- スクリーンショットは `e2e/screenshots/` に保存され、HTML レポートにも添付されます。

## シナリオ一覧

### 01-auth: 認証 (新規登録・承認・ログイン・PWリセット)

| # | 実行動作 | 期待すること |
| --- | --- | --- |
| 1 | 未入力のまま登録する | 各項目に必須エラーが表示される |
| 2 | 条件を満たさないパスワードで登録する (7文字 / 英大文字なし / 英小文字なし / 数字なし) | パスワードの条件エラーが表示される |
| 3 | 確認用に別のパスワードを入力して登録する | 不一致エラーが表示される |
| 4 | 目のアイコンを押す | 入力中のパスワードが表示・非表示に切り替わる |
| 5 | 最初のユーザーを登録する | 管理者としてダッシュボードに遷移する |
| 6 | 登録済みのログインIDで登録する | ログインID欄に重複エラーが表示される |
| 7 | 登録済みのメールアドレスで登録する | 登録済みとは断定せずにログイン・再設定へ案内される |
| 8 | 2人目のユーザーを登録する | 承認待ち画面に遷移する |
| 9 | 承認前のユーザーでログインする | 承認待ち画面に遷移する |
| 10 | 管理者が新規登録を承認する | 承認待ちから消え、本人へ承認メールが送信される |
| 11 | 承認後のユーザーがログインIDでログインする | ダッシュボードに遷移する |
| 12 | メールアドレスでログインする | ダッシュボードに遷移する |
| 13 | 誤ったパスワードや存在しないID・メールアドレスでログインする | どれも同じエラーメッセージが表示される |
| 14 | 短時間にログイン失敗を繰り返す | 一時的に制限されている旨が表示される |
| 15 | 未ログインでダッシュボード配下を開く | ログイン後に元の画面へ戻る |
| 16 | 一般ユーザーが管理者メニューを開く | ダッシュボードに戻される |
| 17 | ログアウトを確定する | ログイン画面に戻り (入力値は残らない)、ダッシュボードを開けなくなる |
| 18 | 存在しないメールアドレスでPWリセットを申請する | 登録済みと同じ受付メッセージが表示される |
| 19 | PWリセットを申請する | 管理者の承認後に届くURLから再設定し、新しいパスワードでログインできる |
| 20 | 無効なトークンで再設定画面を開く | URLが無効である旨が表示される |

### 02-settings: ユーザー設定 (2人目のユーザー)

| # | 実行動作 | 期待すること |
| --- | --- | --- |
| 1 | 現在のパスワードを誤って入力し変更する | 現在のパスワード欄にエラーが表示される |
| 2 | 現在と同じパスワードを新しいパスワードにする | 異なるパスワードを求めるエラーが表示される |
| 3 | 条件を満たさない新しいパスワードにする | パスワードの条件エラーが表示される |
| 4 | 現在と同じメールアドレス (大文字違い) を入力する | 新しいメールアドレスを求めるエラーが表示される |
| 5 | 他のユーザーのメールアドレスに変更する | 確認後に重複エラーが入力欄に表示される |
| 6 | メールアドレスを変更する | ダッシュボードに完了バナーが表示され、設定に反映される |
| 7 | パスワードを変更する | 完了バナーが表示され、新しいパスワードでのみログインできる |

### 03-memo: ダッシュボード (メモ入力・凡例テキスト)

| # | 実行動作 | 期待すること |
| --- | --- | --- |
| 1 | メモ入力ダイアログを開く | 日付の初期値が今日で、今日より前は選べない |
| 2 | 過去の日付を入力して保存する | 保存されず、ダイアログが開いたままになる |
| 3 | 3か月先の月末より後の日付を入力して保存する | 保存されず、ダイアログが開いたままになる |
| 4 | 空のメモを保存する | メモの入力を求めるエラーが表示される |
| 5 | 6行のメモを保存する | 行数の上限エラーが表示される |
| 6 | 1行21文字のメモを保存する | 1行の文字数の上限エラーが表示される |
| 7 | メモを保存する | 保存のトーストが表示され、次回は直前の日付が初期値になる |
| 8 | 入力済みの日付に保存する | 新旧比較ダイアログで確認後に上書きされる |
| 9 | 凡例テキストを編集する | プレビューに反映され、再度開いても保持される |
| 10 | 月をまたいで多数の空き枠を登録する (今日の2〜3日前、2〜45日後) | 登録データ一覧に登録のある月がすべて表示される |

### 04-records: 登録データ一覧・月別一覧

| # | 実行動作 | 期待すること |
| --- | --- | --- |
| 1 | 登録データ一覧を開く | 登録のある月と今月から3か月先までの月が新しい月から順に表示され、今月が強調される |
| 2 | 月をタップする | 月別一覧に遷移し、入力済みの日だけが開いている |
| 3 | 全て閉じる・全て開くを押す | 入力済みの日だけがまとめて開閉される |
| 4 | 入力済みの日を編集する | UPDATED バッジが付き、内容が更新される |
| 5 | 入力済みの日をクリアする | 確認後に未入力になり、UPDATED バッジが付く |
| 6 | 未入力の日にメモを追加する | NEW バッジが付き、入力済みになる |
| 7 | 前の月・次の月で切り替える | 3か月先の月では次の月が押せない |
| 8 | 存在しない年月を開く | 年月が正しくない旨が表示される |
| 9 | 「この月でストーリーズを作成」を押す | エディタが対象月の月指定で開く |

### 05-backgrounds: 背景画像管理

| # | 実行動作 | 期待すること |
| --- | --- | --- |
| 1 | 背景画像管理を開く | 4つの空きスロットが表示される |
| 2 | 対応していない形式の画像を選ぶ | エラーが表示され、登録されない |
| 3 | サイズの大きな写真 (約10MB・3024×4032) をアップロードする | 長辺1920px以下・約1MB以下に軽量化されて登録される |
| 4 | 残りのスロットに画像を登録する | 4枠すべてにサムネイルが表示される |
| 5 | 画像を上書変更する | 新しい画像に差し替わる |
| 6 | 画像を削除する | 確認後に空きスロットに戻る |

### 06-editor: ストーリーズエディタ

| # | 実行動作 | 期待すること |
| --- | --- | --- |
| 1 | エディタを開く | データのある今月 (なければ直近の月) が選ばれている |
| 2 | 「過去日を含める」を ON にする | 今日より前の空き枠も一覧に表示される (今日が月初の場合はスキップ) |
| 3 | 期間指定で 7日・14日・28日を選ぶ | 件数に応じてバッジの表示サイズ (大・中・小) が切り替わる |
| 4 | チェックを外す | 件数とキャンバスのバッジが減り、期間を変えても除外が保持される |
| 5 | 全解除・全選択を押す | 表示件数が0件・全件に切り替わる |
| 6 | 空き枠リストからメモを編集する | UPDATED バッジが付き、プレビューに反映される |
| 7 | 背景画像を選ぶ | キャンバスの背景が切り替わり、再度開いても選択が保持される |
| 8 | 全画面プレビューを開いてタップする | 全画面表示が解除される |
| 9 | 28日間の空き枠を全画面表示する | はみ出し警告なしで1画面に収まる |
| 10 | 1か月分の空き枠を月指定で表示する | 月全体のスクリーンショットを保存できる |
| 11 | 5行の長いメモを含む7日間を表示する | 文字が自動的に小さくなり、1画面に収まる |
| 12 | 全日を5行の長いメモにして28日間を表示する | 入りきらない旨がトースト・警告文で通知される |
